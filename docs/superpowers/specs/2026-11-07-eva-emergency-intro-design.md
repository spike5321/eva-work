## 3. 方案选择

推荐：新增独立 React/SVG 警报首页，CSS 负责整体透视；保留现有 React 启动控制器与 Canvas 后续演出。这样文字、时钟和几何可以清楚缩放，透视不用重新开发投影引擎。

其他路径的取舍：直接用仓库 SVG 最快，但构图不符合图 1；全部改为 Canvas/WebGL 可以实现，却扩大动画引擎、文字投影和测试范围。本方案不新增 Three.js、GSAP、插件宿主或其它运行依赖，不搬入 DSH 的音频、双驾驶员选择与聊天注入逻辑。

## 4. 新首页：红黑透视仪表阵列

### 4.1 构图

- 黑色整屏底 `#000000`；主体红 `#ef060c`，较暗边缘 `#b90308`，黑色字与刻度 `#030101`。
- 同一块平面的蜂巢仪表板居中，左端缩小远离、右端放大靠近。全部单元共用透视，不能给每个格子独立随机旋转。
- 1440×900 参考视口下，投影后主体目标宽约 58–70vw、高 76–86vh；四周保留黑色空间，不能裁掉最右上/右下六边形。超宽屏按高度限制主体，不能横向拉伸铺满。
- 透视参数试稿起点：`perspective: 1100px`、`rotateY(-28deg)`、`rotateZ(-2deg)`；允许 Y 轴在 -24° 至 -34°、Z 轴在 -4° 至 0° 内按最终截图校正。画面结果以“右侧更大、左侧更小”为准。
- 蜂巢缝隙采用清晰黑色隔断，基准宽 8–12px。所有字、数值、三角形与格子一起处于同一投影平面。
- 中央数字区占主体平面宽度约 40–46%，采用融合的大块多边形轮廓，不在中央挤入一组等大的小卡片。

### 4.2 内容结构

以规则的尖角向左右六边形网格为骨架，依据图 1 组织约 18–22 个可见区域，中央合并单元可计为一个区域。区域数量允许因外轮廓微调，以下视觉关系必须成立：

| 位置 | 内容与处理 |
| --- | --- |
| 左右边缘 | 重复 EMERGENCY 六边形，上下实心黑三角；右侧单元明显较大 |
| 中央 | 七段大数字 `HH:MM:SS`，视觉权重最高；配小字 `LOCAL SYSTEM TIME` |
| 左中 | `PILOT / AYANAMI REI`、`UNIT / EVA-00`、`LINK / STANDBY` 等身份信息 |
| 中上 | 一块状态柱图，标签 `SIGNAL MONITOR`；是装饰性信号，不接麦克风、不暗示真实音频采集 |
| 右上 | `內部 / INTERNAL` 警示牌式图形，有少量斜纹，沿用整体平面 |
| 右中 | 竖排 `緊急狀態` 作为副标题，避免恢复成「零號機」大标题 |
| 下方 | 一块 NERV 素材格与少量系统状态格；使用现有 motto-free 标志，黑色剪影适配红底 |

图 1 的 IKARI / EVA UNIT 01 不照抄，保留本项目 Rei / EVA-00 身份。新汉字必须通过实际嵌入 OTF 的字形覆盖检查；缺字时改文案或整句用无衬线，不能逐字混合回退。

中央数字默认采用本机本地时间，每秒更新一次，不作为任务剩余时间。时钟服务允许注入 `Date` 以便截图固定到 `04:54:32`；正式画面不固定这个数字。采用七段矢量数字与冒号，不直接复用现有附带 `%` 的同步率绘制函数。静态/动态状态的细小标记可写 `DEMO`，不要再加一段说明破坏构图。

### 4.3 字体与动效

- 英文警报使用粗无衬线，字面紧凑；汉字副标题用现有 `EvaDisplay` 900；读数用七段几何。
- 默认静音。主体透视固定，不跟随鼠标转动，不持续摆镜头。
- 六边形分组缓慢呼吸：周期约 2.4 秒，亮度/透明度在 0.82–1.0 间变化，每组错开 120–180ms。中央读数保持稳定，避免全屏红黑频闪。
- 扫描纹理只做 3–5% 强度，优先简单重复纹理；不引入整屏高成本噪声滤镜或大面积霓虹外发光。
- 默认保留现有“等待用户开始”的逻辑：点击警报主体或底部 `啟動接續 / INITIATE LINK` 开始后续流程；底部按钮为真实 DOM 按钮，可被键盘访问。
- `ESC / 略過` 位于底部中央独立一行，与主操作至少间隔 16px；点击它和 Escape 都直接进入工作台。焦点落在略过按钮时，Enter 必须执行略过，不能被全局开始事件截走。
- 刷新不因系统时钟、呼吸动画或倒计时自动进入下一阶段；用户已有“下次直接进入工作台”偏好继续生效，主动重播仍显示新首页。

## 5. 第二屏：居中 NERV + 横排系統喚醒

### 5.1 布局

以整个视口几何中心 `(width/2, height/2)` 为锚点，而不是当前为同步环预留确认带的 `stageLayout().cy`。NERV、中文标题、英文副标构成上下居中的一个整体：

1. 顶部：现有 `public/assets/nerv.png`，红色、保持天然宽高比，无 PSD 替换、无拉伸、无新增口号。
2. 中部：横排 `系統喚醒`，四字为同一行，深墨蓝 `#0c1e31`，实际 Matisse EB。
3. 底部：横排 `SYSTEM WAKE / FIRST CHILD`，低调等宽小字。

1440×900 基准：整体内容高度约 272px，NERV 包围盒高 144px，标志到中文间距 20px，中文字级 80px，水平压缩 .82，中文到英文间距 16px，英文字级 12px、字距 2px。以整体实际绘制边界计算居中，允许纵向 ±12px 光学校正。

缩放因子 `s = min(width/1440, height/900)`，桌面尺寸下将其限制在 .8–1.6。按 s 等比缩放以上数值；标题的测量与包围盒必须计入水平压缩，不把未压缩文本宽度用于居中。

### 5.2 避免两个视觉中心

- 删除原左侧用于唤醒的纵向大字、侧边竖线和旋转英文，不能搬完后留下旧副本。
- 居中唤醒阶段暂时隐藏顶部左侧的小 NERV/EVANGELION-00 品牌组合，避免同屏出现两个红 NERV 主标；原顶部边线、右侧机体信息和边轨可保留。
- 中央 NERV 组合淡出后，原角落品牌在 LCL 开始时淡入；这是阶段性显隐，不是永久删除品牌。工作台左上品牌完全保持原样。
- 原背景中心小圆环在唤醒阶段关闭，避免与 NERV/文字重叠；外围线稿继续存在，中心区域适度压低对比。到同步阶段必须恢复现有主同步仪表。
- 不全局修改 `stageLayout().cy`，否则 400% 仪表和确认栏会被连带移动。使用独立 `wakeLayout()`。
- 背景图层仍在文字后，橙色 LCL 仍在蓝色边轨前。不要为居中组合新增白色卡片或模糊玻璃背景。

## 6. 状态、时间与衔接

流程：红黑警报首页等待 → 用户启动 → 短过渡 → 居中唤醒 → 原 LCL 注入/排空 → 原同步率 400% 暂停 → 原驾驶员确认 → 原工作台。

| 阶段 | 时序/行为 |
| --- | --- |
| 首屏等待 | 不推进既有 sequence time；时钟和低频呼吸可以运行 |
| 用户开始 | 把 sequence time 设为 0 并开始推进；红黑 DOM 覆盖层在 scene time 0–0.65 秒退出，下面蓝白画面同步显露 |
| 唤醒主画面 | 新组合在 scene time 0.25–0.95 秒淡入，0.95–2.3 秒稳定显示，2.3–2.8 秒淡出 |
| 后续阶段 | 所有现有节点原值保留：LCL 2.8–6.6，排空 7.0–9.5，同步 8.5–14.9，14.9 等待确认，transfer 15.1，handoff 19.7–21.1，duration 21.4 |

上述秒数均为现有 scene time；slow=true 仍按 .8 倍推进，所以实际过渡约 .81 秒。新过渡位于原时间线内部，不把全部后续时间点后移，也不额外增加固定等待。不要先做一张 NERV 字标警报，再做用户图仪表，形成重复开场。

过渡只用透明度与轻微明度变化，不做白闪、爆炸、镜头急推。红色首页完全退出后，蓝白阶段不再残留红黑覆盖层。

资源未就绪时开始按钮禁用，略过始终可用；字体或图片失败时展示可读回退并保留略过，不允许空白锁死。反复点击开始只能启动一次。页面切后台暂停序列和呼吸；回前台不补算隐藏期间的 sequence time，本机时钟可以恢复为真实时间。

新首页与过渡尊重减少动态效果：保留静态警报与开始按钮，取消呼吸和渐变过渡。对既有整段 LCL 的减少动态效果改造不扩展至本轮；它是前次审查的独立遗留事项，不能宣称整套启动已完全适配。

## 7. 当前代码落点与保护范围

当前开场由 `unified-sequence.js` 的 splash 分支调用 `drawTitleCard()`；纵排唤醒直接写在同文件 wakeAlpha 块内。常驻角落品牌又在同文件下部单独绘制，因此移动唤醒时要同时处理两处 NERV 的关系。

推荐新增：`src/boot/EmergencySplash.jsx`、`emergency-splash.css`、`emergency-layout.js`、`EmergencyDigits.jsx`、`wake-layout.js`、`wake-title.js`。

修改：`src/BootSequence.jsx`、`src/boot/unified-sequence.js`，按需调整 `scripts/check-font.py` 和相关 QA hook；新样式仅作用于新首页，避免追加全局覆盖。

`title-card.js` 的旧开场调用必须断开；确认没有其它引用后可以删除文件。删除的是标题页功能，不是清空项目中的「零號機」「EVA-00」「EVANGELION-00」字符串。

必须保持：App 的示例聊天、偏好存储、重播入口、inert 保护；既有字标及 Rei 线稿；七段同步读数、3px 环、400% 同帧转红、暂停确认与连续交接；蓝色边轨和橙色 LCL；静音。

保持 `.openai/hosting.json`、`worker/index.js`、`scripts/prepare-sites-build.mjs`、`tests/sites-worker.test.mjs` 原有职责与内容。UTF-8 中文文件用 apply_patch 或明确 UTF-8 的文件工具编辑，禁止 PowerShell 文本重写链路。

## 8. 验收标准

- 首次打开是红黑透视蜂巢与中央七段时间；不再出现「零號機」巨型标题卡。
- 右侧蜂巢明显比左侧近且大，整块仪表统一透视；不出现平铺 wallpaper、孤立卡片或仓库的正面 NERV 海报。
- 新首页保留黑色边距、数字主次和清楚的开始/略过入口；无作者水印作为产品装饰，无新增音频。
- 1440×900、1920×1080、1280×720 三种桌面尺寸下，主体、操作和唤醒组合不裁切；2560×1440 与 3440×1440 验证等比缩放与超宽留白。
- 第二屏只有一个主要 NERV 组合，整体居中，系統喚醒横排；原左边竖排及背景中心环不争夺焦点。
- 唤醒消退后恢复原角落标志；同步圆环与确认带位置和颜色行为不变。
- 鼠标、Tab+Enter/Space、Escape、略过、重播、直接进入偏好都正确；无双启动、无多份定时器、无退出后残留覆盖层。
- 新增场景可在 QA 中冻结；现有 pause/resume/start/splash/seek/confirm hooks 保持可用，splash 能完整复位确认与退出状态。
- 构建与现有 Sites worker 测试通过；新场景无控制台异常、字体缺字与资源 404。逐帧视觉验证和交互验证各有截图/记录，不能用一次 build 代替。

## 9. 交接边界

本规格不要求执行者新增移动端、换工作台主题、加声音、做驾驶员选择、接入真实 Codex、发布站点或重写启动引擎。需要扩大范围时单独说明，不把前一轮审查中的所有建议顺手实施。

交付物应是已运行可检查的本地预览、首屏与居中唤醒截图、后续流程回归记录，以及简短修改说明。执行者应先完成两张静态关键画面的对齐，再加入呼吸与转场。
